# Adding a phone-app module

A module is one server file and one app file (plus a stylesheet). Ping is the example: `server/modules/ping.ts`, `app/modules/ping.js`, `app/modules/ping.css`.

1. Server: create `server/modules/<name>.ts` exporting a `Module` (`server/modules/types.ts`): `name`, `handle(ctx)` returning a `Response` or `null` for "not mine", optional `jobs` (`{ id, at: "HH:MM" | every: "15m" | "1h", days?, run(ctx) }`).
2. Register it: one import and one array entry in `server/modules/index.ts`. Your routes are `/api/v1/mod/<name>/<rest>`; `ctx.path` is the `<rest>` part. Use `ctx.db()` for SQL on this user's agentos db, `ctx.agentos([...])` for the CLI, `ctx.ai.claude(...)` / `ctx.codex(...)` for proposals, `ctx.push(title, body)` for a notification, `<ctx.dataDir>/mod/<name>/` for files.
3. App: create `app/modules/<name>.js`. First line `const { AOS } = window;`, then `AOS.css('modules/<name>.css')` and `AOS.register({ id, title, icon, order, figure, page(el), cards: { todayTop(el, m), life(el) }, onData() })`.
4. Register it: one `import './<name>.js';` line in `app/modules/index.js`.
5. `page(el)`: render your whole page into `el` (give it a `<h1 class="large-title">` or a `.detail-hero`). It runs once when the page opens from More or `AOS.openPage(id)`; refresh it yourself from `onData()`, which fires after every sync.
6. Cards are optional and run on every render pass with the same child element per module, so render synchronously from cached state (fetch in `onData()`), keep them under one screen, and leave the element empty when there is nothing to say.
7. Fetch with `AOS.api('/api/v1/mod/<name>/...', { method, body })`; it carries the session (cookie on the web, Bearer token in the iPhone app) and throws `{ status, message }` on errors.
8. Styles go in `app/modules/<name>.css` only, written against the design system (`app/ui/STRUCTURE.md`, tokens at the top of `app/ui/system.css`): surfaces `var(--e1-bg)` + `var(--e1-box)`, text `var(--ink)` / `--ink-2` / `--ink-3`, controls `var(--ctl)`, the shared classes (`.group > .lrow`, `.chip-btn`, `.act`, `.small-btn`, `.pill`, `.segmented`), area colour only as dots, rails and 15% washes (`AOS.areas.get(slug).color`), no horizontal scroll, sentence case, nothing under 12px, inputs at 16px. Both skins (Obsidian, Matte) and light must read right; a rule only one skin needs is `:where(:root[data-skin="matte"]) .x { … }`.
9. Toasts, haptics and sheets: `AOS.toast(text, undo?)`, `AOS.haptic('light'|'medium'|'selection'|'success')`, `AOS.makeSheet(el, { detents, scrimFor })` on a `.sheet` element you append to `#screen`.
**More's row: `figure()`.** Optional. Return `{ value, label }` from cached state (synchronously, no fetch) and More shows the module as one row: title, `label` under it, `value` at the end (e.g. `{ value: '3', label: 'Repeated asks' }`, `{ value: '19:00', label: 'Sits Saturday' }`). Return `null` or nothing to show the title alone. Errors are caught and logged.

**The module page kit** (`app/ui/screens/content.css`): `.mp-head` (+ `.mp-ic` icon tile, `.mp-head .sub`) for the page head; `.mp-card` for a surface block (stacked cards space themselves); `.mp-big` / `.mp-k` / `.mp-v` for a figure with its key and value; `.mp-st` for a status word; `.mp-why` / `.mp-note` / `.mp-hint` for secondary text; `.mp-acts` (card actions) and `.mp-racts` (row actions); `.mp-add` for an add field; `.mp-more` to fold a long list; `.mp-load` for a loading state; `.mp-foot` for the page's footer action; `.mp-text` for long text; `.mp-aglyph` for an agent glyph. Use these before writing module-specific classes, so module pages read as one family.

10. Test on your own port (FOUNDATION.md section 7), open More, tap your row, then check the Today and Life slots. `scripts/build-www.mjs` copies `app/modules/` into the native build.

`AOS` = `{ api(path, opts), data(), areas (Map slug → area), today ("YYYY-MM-DD"), user ({ id, email, name, role }), toast(text, undo?), haptic(kind), makeSheet(el, opts), setTab(tab), refresh(force?), esc(s), fmt(min), css(href), register(mod), openPage(id) }`.

**A module can fill a tab.** `AOS.register({ id, title, page(el), tab: 'clients' | 'content' })` puts the module's page in that tab of the tab bar (Today · Jobs · Clients · Content · More) instead of More's list; `page(el)` runs once, the first time the tab opens, and `onShow(el)` (optional) every time it opens again. `AOS.openPage(id)` then opens the tab. `AOS.registerTab(id, { render(el, page), onShow?(el, page) })` does the same without a module. Content uses `tab: 'content'`; the clients module fills Clients.

**The design system on `AOS`** (`app/ui/ui.js`):
- Rings, the app's motif: `AOS.ring(p, hue, size, w, { inner, cls, k, id, delay, label })` returns markup (`hue`: `today | jobs | clients | content | life | needs`; `p` may pass 1 and the ring laps itself; `k` puts a marker across the track); `AOS.ringSet([[p, hue, opts], …], size, w, gap)` nests them; `AOS.setRing(el, p)` moves one from where it is; `AOS.pulse(root)` draws a page's rings in (Obsidian's light blooms, Matte's ink goes in) and counts up any `[data-count="n"][data-fmt="int|hm|dur|dec|pct"]`. Tabs and pushed pages pulse on open by themselves; call it after you redraw a page's rings yourself. Put `--ring-bg` (the colour under the ring) on an ancestor.
- Segmented control: `AOS.seg(name, [[value, html, count?], …], selected, { cls, label, role: 'tab' | 'radio' })` returns markup; a tap moves the lens and fires a bubbling `segchange` event (`e.detail` is the value) on the control. `AOS.selectSeg(el, value)` sets it from code.
- Skins and theme: `AOS.skin()`, `AOS.setSkin('obsidian' | 'matte')`, `AOS.skins`, `AOS.theme()` (`auto | dark | light`), `AOS.setTheme(pref)`, `AOS.skinSeg()` / `AOS.themeSeg()` (the controls, working wherever drawn).
- `AOS.peek(html, [{ label, icon, run }])` and `AOS.closePeek()` (hold to preview), `AOS.onHold(root, selector, fn, ms)`, `AOS.icons.<name>` (line icons), `AOS.visiblePage()`, `AOS.openTasks(list?)`, `AOS.openLife({ goals })`, `AOS.syncStatus()` (`ok | offline | error`: whether the last sync reached the PC, so a page never claims the PC is online when it is not).
